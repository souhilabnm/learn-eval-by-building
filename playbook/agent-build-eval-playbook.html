Rules that hold in every case

Look before you automate
Read real traces first. Metrics you invent before reading data usually measure the wrong thing.
One failure, one check
Each judge or code check tests a single failure mode with a pass or fail answer. Avoid 1-to-5 scores.
Trust the judge only after testing it
Compare the LLM judge with your own labels on a held-out set. Track true positive and true negative rates.
Make a golden set early
Label a sample of real answers yourself. It is the answer key that tells you whether your judge can be trusted. About 50 is a rough starting point; what matters is having enough failures and enough good answers in it.
Keep a regression set
Every failure you fix becomes a permanent test case, so it cannot quietly return.
Cheaper first
Use code checks (format, schema, regex, tool arguments) before any LLM judge.
Domain expert owns quality
The person who knows what a good answer is decides the failure categories, not the engineer.

The use case

The Recipe Chatbot is a small AI agent from your AI evaluations course. A person types what they want to cook and it replies with a recipe. It is a good practice project because it is simple enough to understand fully and still fails in interesting ways.

Under the hood: a web page for chatting (frontend), a Python server that receives each message (FastAPI), and a library that calls the AI model (LiteLLM). The course has five homeworks that follow the nine stages from page 1.

HW1
Prompt engineering
HW2
Error analysis and failure taxonomy
HW3
LLM-as-judge evaluation
HW4
Search (retrieval) evaluation
HW5
Agent failure analysis

Before you start

  1. Create a course folder (any name, any place).
  2. Clone the project with Claude Code. In the Claude app, go to the Code tab, start a new session, select your course folder, and type: 
    Clone https://github.com/souhilabnm/recipe-chatbot.git into this folder
    This creates a recipe-chatbot folder inside your course folder.
  3. Open the project. Start a new session in the Code tab and select the recipe-chatbot folder.
  4. Let Claude Code set it up. Type: 
    /learner-setup
    It installs everything and creates your .env file. It is done when you see Setup OK.
  5. Add your model and API key to .env, in the recipe-chatbot folder.
    Windows: right-click .env > Open with > Notepad.
    Mac: in Finder press Cmd+Shift+. (period) to show hidden files, then right-click .env > Open With > TextEdit.
    Fill in these three lines (Anthropic example): 
    MODEL_NAME=anthropic/claude-sonnet-5-5
MODEL_NAME_JUDGE=anthropic/claude-haiku-5-5
ANTHROPIC_API_KEY=paste-your-key-here
    Using OpenAI instead: 
    MODEL_NAME=openai/gpt-4.1-mini
MODEL_NAME_JUDGE=openai/gpt-4.1-nano
OPENAI_API_KEY=paste-your-key-here
    No spaces around =, no quotes. Save: Ctrl+S on Windows, Cmd+S on Mac. Keep your key secret: never paste it into chats or screenshots.
  6. Start the chatbot. In Claude Code, type: 
    Start the chatbot with: uv run uvicorn backend.main:app --reload --reload-include '*.md'
    Then open http://127.0.0.1:8000 in your browser.
    If you see Got unexpected extra argument (README.md) (common on Windows), use this instead. The only difference: after editing the system prompt, stop the server with Ctrl+C and start it again. 
    Start the chatbot with: uv run uvicorn backend.main:app --reload
  7. Get guided, stage by stage. In Claude Code, type: 
    /evals-coach
    It checks what you have done, tells you which stage you are on below, and coaches you through it one step at a time. You do the writing and labeling; it explains, reviews your work and moves you to the next stage. Type it again any time to pick up where you left off.

What happens when you send one message

Read from top to bottom. "You" is the person using the chatbot. Each column is a part of the system. Arrows show who passes what to whom. The orange arrow is where a record is saved. The green box is where evaluation happens.

Why this matters: evals can only check what was saved. These four boxes tell you what the chatbot records today, what is missing, and what to ask engineering for.

Saved today
Every chat in your browser leaves a small record (the question and the answer). Runs from the bulk test leave one file per run.
Not saved today
Which AI model answered, which version of your instructions was used, how long it took and what it cost. If the AI provider fails, nothing is saved for that message.
What a full record adds
Those four extras, plus every search or tool step in agents that have them. You do not add this here. You now know to ask engineering for it.
Good to know
The hidden instructions (the system prompt) are read once when the app starts. That is why the app restarts when you save changes to that file.

The project folders, and what you can reuse

What each folder and file is for, and whether you can carry it into another chatbot project (a support bot, a travel bot, and so on). Based on reading the files themselves.

Reuse as iscopy it, no edits Reuse + changecopy it, edit a few lines Replacewrite your own version Course onlylearning material, recipe data
Shortest path to a new chatbot
  1. Rewrite backend/system_prompt.md for the new job. This one file is what makes it a recipe bot.
  2. Change the name and the "Ask for a recipe..." text in frontend/index.html.
  3. Replace data/sample_queries.csv with requests for the new bot. Keep the first line id,query.
  4. Empty annotation/traces/ so old recipe chats do not mix with the new ones.
  5. Rename the project in pyproject.toml.

The server, the model connection, the bulk test and the trace recording carry over unchanged.

backend/ Reuse + change

The chatbot itself: the server and the link to the AI model.

main.pyReuse as is
The server. Receives each message, gets the answer, saves one trace file per message in annotation/traces/, and serves the chat page.
Change: nothing to run it. Later, ask for the model name, prompt version, time and cost to be added to each saved record.
utils.pyReuse as is
Reads the system prompt file and the model name from .env, adds the instructions to the conversation and calls the model through LiteLLM. Nothing in it is about recipes.
Change: nothing.
system_prompt.mdReplace
The hidden instructions ("You are an expert chef..."). The only thing that turns a general model into a recipe bot.
Change: write the new bot's role, rules, format and defaults. Start from your stage 1 spec.
retrieval.pyReuse + change
BM25 search over a recipe file. Not used by the chat page; it is for HW4. Only needed if the new bot answers from your own documents.
Change: point it at your documents. It expects recipe fields (name, ingredients, steps, tags), so rename them to your fields.
query_rewrite_agent.pyReuse + change
Rewords a user's question into better search words before searching. Goes with retrieval.py.
Change: its instructions talk about cooking methods and equipment. Rewrite them for your subject.
evaluation_utils.pyReuse + change
Scores search quality: recall@k and MRR. The method works for any search.
Change: it looks for a field called source_recipe_id. Rename it to your document id.
